# P17 - Post-launch

## Goal
Operate Repair Empire from evidence rather than feature impulse.

### P17-T01 Incident process
Define owner, severity, mitigation, communication notes and post-incident follow-up.

### P17-T02 First telemetry review
Review activation, session behavior, retention indicators, economy and monetization funnels after sufficient data.

### P17-T03 First balance patch
Make only changes supported by data or clear player-blocking evidence; increment balance version.

### P17-T04 Content cadence
Prioritize new job content, district dressing, cosmetics and contracts before adding large new systems.

### P17-T05 Backlog prioritization
Classify requests as:
- retention problem
- progression/economy problem
- UX problem
- content demand
- technical risk
- monetization opportunity

## LiveOps rules
Do not change multiple core economy variables simultaneously without a reasoned experiment.
Keep schema migrations backward-aware.
Preserve paid entitlements.

## Definition of Done
A repeatable operating loop exists: observe -> diagnose -> change -> version -> measure.
